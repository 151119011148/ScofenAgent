1 这次解决什么

  • V6＝V5 的第二半：v1.4 实测的边界——杀掉进程再开，选中旧会话接着问，屏上 4 行历史都在（库里读出来的），模型答 Final answer: 不记得，本题 in 3,384。屏与记忆是两套账。
  • 为什么不是"重放屏幕文字"：agents.py:767-769 的 write_memory_to_messages() ＝ system_prompt.to_messages() ＋ 逐条 step.to_messages()，模型读的是 memory.steps，不是 chatbot 那串给人看的卡片。重放屏幕文字要重定「本题累计」的边界，且 in 随历史线性涨。所以存字段本身。
  • 存哪些字段有根据：steps 里只会出现 TaskStep/ActionStep/PlanningStep——FinalAnswerStep 只 yield 不 append（agents.py:609-611），超步数时 :636 append 的是带 AgentMaxStepsError 的 ActionStep。存这些＝存"模型下一轮读到的那一串"。
  • D7＝v1.4 定位的那条竞态：agents.py:470 在新 run 开头把 interrupt_switch 清回 False，所以落在待批卡之前的停止等于空放，后到的待批没人结算（v1.4 实测死停 142.4s）。取 v1.4 §7 写下的两条修法里的第 ② 条：_stop 给本轮打取消号，闸入队那一刻看到号直接按 cancelled 结算。

6 口径变化

  1. 记忆档位：每会话一份、只在进程里 → 每会话一份、落库。库里形式 {"fmt":"v1","steps":[…]}，一行一个 session_id。
  2. 存的是字段，不是屏幕文字；model_input_messages 与图片三兄弟不存 → 带图的观察值重启后进不了模型上下文【多图会话未验证】。
  3. 文本一律原样存，只有 action_output 过 make_json_serializable（utils.py:146-153 会把像 JSON 的串解析成 dict，回放就变字）。
  4. 错误对象是"造"的（__new__ ＋ Exception.__init__）；ToolCall 存 OpenAI function 形状。
  5. 坏数据降级：整块坏＝当作没记忆，单条坏＝跳过那一条。不会因一次异常废掉整条会话。
  6. token 口径不变，跨重启继续涨：2,362 → 2,465 →（重启）2,574 → 2,675 →（审批两步 2,909 + 2,987）→（二次重启）3,091；裸起步恒 2,363；进程档每次重启归零。
  7. 「本题累计」边界不受回灌影响：回灌的是上一题的 steps，本题仍从 0 起算（离线 2l：300/13）。
  8. 停止的语义扩了一格：■ 停止 现在覆盖"本轮之后到达的待批"；被取消的调用照样写进记忆并落库。
  9. 审批等待时间计入步骤耗时（实测 272.9s，真执行 ~1s）：v1.3 起就是这口径，本轮没改。
  10. 体量：my_ui.py 893 → 1,108 行、44,838 → 55,774 B、净 +217 / −2；.rollback/ 10 → 12 份；看板 33 → 34 条（D7/V6 转已上线，新立 V7 侧栏选中态）。
