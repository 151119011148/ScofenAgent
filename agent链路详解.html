1 它到底是不是一个 agent

是。但"是 agent"这件事的判据不是它会聊天、也不是它自称 agent，而是代码里这三样东西同时存在：

判据一：循环。有一个 while 反复把「模型的上一次输出」变成「下一次输入」，而不是单问单答。
agents.py:545

判据二：动作空间。模型输出的不是给人看的文字，而是可执行的结构（工具名 + 参数），由本机真正执行。
agents.py:1361 → tools.py:228

判据三：终止条件。有明确的结束信号（final_answer）和一个兜底上限（max_steps），否则会永远问下去。
agents.py:582-592 / 606

三条都在，所以它是 agent；缺任何一条，它就退化成一个"带 prompt 模板的接口调用"。市面上很多号称 Agent 的东西确实只有模板没有循环。

1.1 但它只能做三件事，这就是它拒绝你的原因

你让它"写个 HTML 页面、按 ai学习 里的代码讲"，它回答"我的运行环境不包含源码、框架代码或文件系统访问能力"。这句话是对的，而且不是客套。把它自己的动作空间打印出来看，只有三个工具：

你之前那次运行的真实输出
import ok, tools: ['max_drawdown', 'annualized_volatility', 'final_answer']

没有读文件的工具，没有执行代码的工具，没有访问网络的工具。所以：

  • 它不可能打开 agents.py——不是"不愿意"，是它的动作列表里没有这个动作。
  • 它不可能生成 HTML 文件——同理，没有写文件的动作。
  • 它能做的是：拿你贴在问题里的数字，调用两个数学工具，再组织成文字。仅此。

而它说"如需可视化流程图，建议使用 Mermaid 或 draw.io 手动绘制"——这是大模型在能力边界外给你的建议性补白，属于纯文本生成，不是它的动作。这个区分很重要：agent 的"能"只等于它的工具列表，其余所有"我建议你…"都是话术。

    整条链路的心脏。条件里那两个变量一个由模型决定（拿到 final_answer 才置真），一个由本地计数决定，模型无法自己延长循环——它只能在这 6 步里想办法。

    把 memory 里所有 system prompt / TaskStep / 上几步的 llm_output / action / observation 全部摊平成消息列表。大模型没有"会话状态"，服务端不记你上一轮，所以每走一步都要把整段历史重新发一遍。

    但你看到的那串"一路涨"的数字是个误读陷阱，这里必须讲清。终端日志和网页界面打印的不是同一个口径：

    • 终端 [Step 4: … Input tokens: 5,732] ← monitoring.py:110-114 里 total_input_token_count += …，是整个 agent 生命周期的累计和；那个 Step 4 也是 len(self.step_durations)，跨问题连续编号，所以你换一个问题它不会从 1 重新开始。
    • 网页 Step 1 | Input tokens: 1,979 ← gradio_ui.py:33 的 step_log.token_usage.input_tokens，是这一步真实发出去的量。

    把累计值逐次相减就还原出真相：你今天的五步真实 prompt 是

    1273 → 1402 → 1458 → 1599 → 1979      (累计: 1273 / 2675 / 4133 / 5732 / 7711)

    所以 prompt 没有暴涨，只是缓慢上涨：因为 reset=False（gradio_ui.py:389 把 self.reset_agent_memory 传给 run()，默认 False），历史确实留着，但你前几轮的问答都只有几十字，累加得慢。最后一问要 1979 是因为你那次的问题最长、且前面三轮问答都进了上下文。

3.1 第二条为什么值得单独说

那是模型在幻觉一个工具。它见过太多带搜索的 Agent，于是顺手写了一个 web_search。链路里发生的事情值得拆开看：

  • 模型没有能力真的去搜索——它只是输出了一段看起来像调用的 JSON。
  • 拦截它的是 agents.py:1464 那几行普通代码：一个字典查键。
  • 关键在最后：报错没有被当成崩溃，而是作为 Observation 塞回上下文，让模型自己修正行为。

结论：Agent 的安全边界不在"模型自觉"，在框架的工具白名单、参数校验、max_steps 熔断这三道闸。你以后评估任何一个 Agent 框架，先别看它的 prompt 写得多漂亮，先找这三处代码在哪、能不能收紧。这比看宣传有用得多。

5 它 vs 我：差距全在动作空间

同样是 agent，为什么我能真给你写出这个 HTML 文件、它不行？把两件事放一起看就清楚了。

你的 my_agent.py此刻和你对话的我
工具数3（两个数学 + final_answer）几十个（读写文件、执行命令、搜索、开浏览器、起子 agent…）
读本地代码不能能，本次就是这样核对行号的
写文件不能能，这个 .html 就是写出来的
步数上限6同样有上限，只是更高
终止方式调 final_answer直接停止输出（没有专门的收尾工具）
记忆进程内存活，重启即失会话内累加，跨会话靠 memory 文件

所以"是不是 agent"和"好不好用"是两件事：架构同类，差别只在给了多少动作，以及有没有权限。你那个 3 工具的 Agent 和我的差别，不是智能差别，是接口差别——这也是为什么学 Agent 的主要工作量其实在于设计动作空间和边界，而不是调 prompt。

6 四个动手实验（按编号挑）

每个都是小改动，能直接看到链路某一层的行为。你回编号我就改。

E1 给它一个读文件的工具

让它真的能打开 agents.py 回答自己怎么实现的，正面回答你这次的疑问。在 my_agent.py 加：

新增一个 Tool 子类，然后塞进 tools=[...]
class ReadFileTool(Tool):
    name = "read_file"
    description = "读取本机文本文件内容，返回指定路径的前若干行。"
    inputs = {"path": {"type": "string", "description": "文件绝对路径"},
              "lines": {"type": "integer", "description": "最多返回多少行", "default": 120}}
    output_type = "string"

    def forward(self, path, lines=120):
        import os
        p = os.path.abspath(path)
        root = os.path.abspath(os.path.expanduser("~/Desktop/study/ai学习"))
        if not p.startswith(root):          # 白名单：只许读学习目录
            raise PermissionError("只允许读取 ai学习 目录: " + p)
        with open(p, encoding="utf-8", errors="replace") as f:
            return "".join(f.readlines()[: int(lines)])

注意上面那句路径检查不是可选的。一旦 agent 有了读文件能力，而它又被云端模型驱动，没有边界就等于把整个 Home 目录暴露给一次网页问答。这条约束必须和工具同时加。

E2 看熔断长什么样

把 my_agent.py 里 max_steps=6 改成 max_steps=1，再问一个需要两步的问题。你会看到 state="max_steps_error"（agents.py:606），而且框架不会给你 final_answer——理解"预算"这件事最直观的一次。

E3 让 token 不再累加

my_ui.py 里改成：

GradioUI(agent, file_upload_folder="./data", reset_agent_memory=True).launch(...)

然后连续问两次，对比网页上那行单步数字。开了它，每问第一问都从 ~1270 起且终端 [Step N 每次都从 1 重新数；不开（你现在这样）历史就留着，单步 prompt 缓慢爬升（1273→1402→1458→1599→1979），终端的累计值一路涨到 7711。要不要跨问题带上下文，就是这一行的取舍——注意它和"同一个问题内带上下文"是两回事，后者是 agent 的本性，关不掉。

E4 故意喂一个错参数

把 MaxDrawdownTool 的 inputs 里 "type": "array" 改成 "type": "number"，再问同样的问题。模型还会传数组，于是撞在 tools.py:1402 那句 Argument prices has type 'list' but should be 'number'。这是理解"接口契约由谁强制"最快的一条路——不是模型遵守，是执行方校验。
