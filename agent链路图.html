4 这张图改版了什么

旧版图（2026-10-28 那一版）现在的代码
泳道只有一条「GradioUI gradio_ui.py:388」，并注明「UI 不含任何 agent 逻辑」拆成 OpsUI(GradioUI) + worker 线程两条泳道。my_ui.py:793 起的那层把计划闸、审批闸、查重闸 monkey-patch 到 agent 的 _run_stream 和每只工具的 forward 上——UI 现在就是链路的一部分，画在一个框里会整章丢掉
「框架默认 20，你设 6」my_agent.py:94 现在是 8，且 planning_interval=8 与它同高：下一次重规划落在第 9 步，而 while step_number <= max_steps 在第 9 步之前就退出了——于是「每题恰好一份计划、题内不重规划」是这两行凑出来的，不是配置了才生效的
动作空间三行：max_drawdown／annualized_volatility／final_answer8 只手（裸）／11 只手（UI），见第 3 章那张表
「闸门三道」8 个决策点：框架 4 道（白名单／参数校验／final_answer／步数熔断）＋ 人装 3 道（计划／审批／查重）＋ 项目自己的 guarded() 路径闸。框架还有第四道 final_answer_checks（agents.py:309），至今没用
「只有穿过百炼那一对箭头才出网」这句话现在是错的。fetch 是真出网的一条动作路径，只是它出在本机子进程而不是模型调用里，且每次要人批
「my_coding_agent.py 只有命令行，还没接 UI」它那 5 只手已被 my_agent.py:9-19 import 进主 agent，屏幕上点的就是这个对象；my_coding_agent.py 同时还是超时／锁温两份常量的唯一来源
「不能读你的代码」能读，且被 guarded() 钉在 ai学习/ 这一个根里；write_file 只落 .agent-staging/，原文件一个字不动
「记忆：进程内存活，重启即失」两份落盘：.agent-history.sqlite3（my_ui.py:33，显示层＋memory）与 .agent-audit.jsonl（my_audit.py:42，每次工具调用一行）。删一条会话会 CASCADE 掉记忆，审计不跟着删
没有 MCP、没有审批、没有查重、没有审计v2.0 之后全都有了，也都有自己的洞。图里金边横条标了三处：args_head 明文、run_python 绕 guarded()、计划闸那份「决策」不进模型 memory

5 一句话对照

2026-10-28 那版现在
它拒绝你时，说话的是谁agents.py:1464 的白名单——它凭空编了个不存在的 web_search同一行还是第一道；但你现在看到的拒绝更常来自人装的三处：审批等人点、查重挡重复、guarded() 管路径
能不能动手不能，只有两只算数的手能读、能搜、能在 staging 起稿、能跑验证、能抓外网——每样都配了一道闸，也都留着一个还没修的口子
成本观测口网页那一行 Step N | Input tokens还是那一行，另外多了 model_input_messages、两份落盘、审计里每次调用的挂起秒数——四套口径，别再拿终端那串累计数当单步

这一版和上一版的差别不是"智能"差别，是接口差别：架构一模一样，多出来的是手和闸。所以学 Agent 的主要工作量在动作空间与边界的设计，不在调 prompt。
